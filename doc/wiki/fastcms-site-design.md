## 1. 背景与目标

### 1.1 现状

- **官网不可达**：`fastcms.xiaojudeng.net.cn` 于 2026-10-15 实测 HTTPS/HTTP 均超时（HTTP 000）；此前核实为 SSL 证书错误 + 根路径 404。官网目前是**转化阻塞项**——用户从 Gitee/GitHub/B 站看到 fastcms 后，没有任何落地承接页。
- **v1 落地页（467 行）的三个断点**：
  1. **市场区全是虚构插件**：6 张卡片（评论系统/智能搜索 Pro/表单收集/会员订阅/公众号增强/AI 客服）无一在仓库库存里，"能卖什么"与"手里有什么"脱节；
  2. **无定价体系**：卡片上散落的 ¥299/¥499 只是孤立示例，没有"免费/订阅/企业"的价格叙事；
  3. **最重要的真实商品没出现**：`ai-subscription-plugin`（AI 模型订阅：月/季/年三档、支付回调签发授权码、官网 OpenAI 兼容中转）是代码里已具备的变现主力，v1 页面零体现。

### 1.2 目标

把官网建成**三段漏斗**，商店只是第三段：

```
引流（Hero/能力/免费源码） → 培育（AI 深度叙事/文档/社区） → 变现（AI 订阅 + 插件市场 + 企业服务）
```

本文定义：站点地图（§3）、落地页逐区设计（§4，已实现为 v2 文件）、插件市场全量分类与定价（§5-6）、代码与设计的诚实对账（§7）、落地路线（§8）。

## 2. 商业模式与红线（网站口径的依据）

以下三条是网站所有文案的边界，来自已拍板的商业模式与 2026-10-15 代码核实：

1. **核心永久免费**（LGPL-3.0），不做付费核心版/闭源 fork。官网必须反复讲"免费"，付费项只能是**服务**与**扩展插件**。
2. **BYOK 是免费承诺成立的前提**：用户自带模型 Key 时 AI 成本不归核心方。因此"开源免费"档必须写清"自带模型 Key 即可用"——这既是承诺，也是定价区里订阅档的对照组。
3. **变现三线**（均有代码依据）：
   - **AI 模型订阅（主力）**：`ai-subscription-plugin`，官网实例与客户实例装**同一个插件**、靠配置区分角色（签发方/使用方授权码格式天然一致）：
     - 官网侧：订阅作为商城商品上架，**月度/季度/年度三档**（`SubscriptionPlan` 枚举，按 `plusMonths` 推算到期）；用户支付成功后由 `IPayBackProcessOrderService` 扩展点（`cms/.../order/`）签发授权码；官网提供 **OpenAI 兼容中转端点**，真 Key 只留在官网；
     - 客户侧：后台粘贴授权码 → **本地公钥验签**（官网不可达也能判断"付没付费"，不因官网抖动误锁）→ 写入 `ai_model_config`（`provider=fastcms`、`base_url` 指向官网中转）→ 模板编辑/文章编写/生图可用；
     - 门禁方式：AI 请求必须经官网中转，**授权过期时中转返回 401**——只挡 AI 功能，网站前台与后台其他功能照常，对核心零侵入。
   - **插件市场**：18 个非示例插件库存（§5 全量表），统一资产容器（一个 jar 可携带技能/组件/工具/功能模块）。
   - **企业服务**：私有化部署、定制插件开发（交付即 jar、热插拔安装）、培训。短期唯一真能大额进账的线。

## 5. 插件市场设计

### 5.1 统一资产容器

一个插件 jar 可同时携带四类资产（2026-10-15 核自 `PluginAssetService`）：

| 资产类型 | 形态 | 示例 |
|---|---|---|
| `skill` | SKILL.md 技能包（frontmatter + 正文，正文按需加载进提示词） | 文章写作 4 技能、模板规范 |
| `component` | HTML 组件 + 注册 JS，装完进组件菜单供 AI 选用 | twx 组件包 |
| `tool` | AI 工具函数（Python 沙箱） | —（库存暂无，机制已具备） |
| 功能模块 | Controller/Mapper/模板/数据表/前端页 | 微信五件套、付费下载等 |

前端标签由实际资产自动推导（`ui/src/views/plugin/index.vue`），**不靠手填**——市场分类以这个机制为准。

### 5.5 插件详情页（已实现原型：`doc/wiki/fastcms-market-detail.html`）

**设计原则：详情页 = 卡片的展开（同构）**——卡片上的名称/徽标/资产标签/价格全部保留在首屏，往下逐层加深（能力 → 兼容 → 日志 → FAQ），不做独立的一套信息架构。付费决策页需要 SEO 与深度，故用**整页**而非后台那种 620px 抽屉（抽屉是后台管理形态，公开站不适用）。

**布局：面包屑 + 双列（左信息列 + 右 340px 粘性购买卡）**

| 位置 | 区块 | 字段/内容 | 状态标注 |
|---|---|---|---|

| 左 | 能力说明 | 一段话讲用户能得到什么 | 真实（以插件 README 为源） |

### 5.6 购买流程（四状态抽屉，与 AI 订阅共用同一链路）

**触发**：详情页 [立即订购] → 右侧 460px 抽屉滑出（ESC / 点遮罩关闭）。**不设独立购买页**——购买是详情决策的延续，抽屉保持上下文；且插件与订阅共用一套，避免两套页面。

**状态机**（原型已实现并浏览器实测通过）：

```
confirm ──[微信支付]──▶ paying ──[回调/轮询成功]──▶ done（终态）
                              └──[15 分钟未支付]──▶ timeout ──[重新下单]──▶ confirm
```

| 状态 | 字段 | 对接 |
|---|---|---|
| confirm 确认订单 | 商品行（名称+规格）/ 授权站点选择 / 优惠券码 / 应付金额（档位 − 券，实时联动）/ [微信支付 ¥N] | 站点从会员中心拉取（前端会员中心已有）；券复用现有 coupon 体系 |
| paying 支付中 | 金额 / 二维码 / 订单号 / 15 分钟倒计时 / 每 2 秒轮询订单状态 | 二维码 = wechat-pay 插件 Native 支付；订单状态 = 现有 `order` 表 |
| done 已发放 | 授权码（FC-XXXX-XXXX-XXXX-XXXX，本地公钥验签）/ jar 下载 / 安装三步 / [去后台安装] | 支付回调 `IPayBackProcessOrderService` 扩展点签发 |
| timeout 超时 | 订单已关闭 / [重新下单] | 订单自动关单（15 分钟） |

**关键设计：插件与 AI 模型订阅共用同一抽屉、同一 `order` 表、同一条授权码签发链路**，区别仅在商品类型（`product_type`：plugin / subscription）与 done 页内容——订阅的 done 页无 jar 下载，改为"后台 → AI 模型配置 → 粘贴授权码"。一套流程两种商品，后端零分叉。

实测记录（2026-10-15，真实浏览器）：四状态流转 ✓、档位切换金额双向同步（含底按钮标签）✓、优惠券抵扣 ✓、倒计时走秒 ✓、授权码签发 ✓；期间修复 2 个原型 bug（动态重建按钮事件丢失、金额标签不同步）。

### 5.7 后端缺口（代码核实，2026-10-15）

| 缺口 | 现状证据 | v3 对策 |
|---|---|---|
| 远程插件索引/列表 API | `PluginController` 只有本地 jar/zip 安装，无 registry | 一期不上"在线浏览"，市场页先静态化（数据人工维护），二期建索引 |
| 商品主数据/定价配置 | 订单表无商品主数据（订阅商品同理） | 一期：官网侧静态商品配置（人工维护）；二期：插件商品表 |
| 插件 license 校验 | 代码库无插件级 license（AI 订阅有独立一套 LicenseCodec） | 一期用授权码 + 私有下载链接替代硬校验；二期视第三方开发者规模再建 |
| 付费 jar 发放 | 无"支付→jar"链路 | 授权码模式（同 §5.6 done 页下载凭据） |

## 6. 定价体系

### 6.1 三档（已实现于 v2 落地页，价格为示例）

| 档 | 价格 | 内容 | 边界 |
|---|---|---|---|
| 开源免费 | ¥0 永久 | 全部核心功能 + 管线 AI 建站（自带 Key）+ 免费插件 | LGPL-3.0，商用不收费 |
| **AI 模型订阅**（主力） | 示例 ¥199 起/月，月/季/年三档 | 官网 OpenAI 兼容中转（免配 Key）+ 全部 AI 场景（模板建站/设计稿先行/文章写作/生图）+ 授权码本地验签 | 只收 AI 服务费；BYOK 免费通道并存，不强制 |
| 企业服务 | 定制报价 | 私有化部署 / 专属模型接入 / 定制插件（交付即 jar）/ 培训驻场 | 按需求报价 |

### 6.2 定价逻辑

- **订阅三档形态是代码定死的**：`SubscriptionPlan`（MONTHLY/QUARTERLY/YEARLY，按 `plusMonths` 推算到期），落地页与商城文案不得超出这三种。
- 订阅价 = 模型调用成本 + 中转服务毛利；年付折扣力度留 15-25%（示例值，未定）。
- 付费插件按**站点/年**计费（与订阅同一续费心智），不做一次性买断——留续费线。

## 9. 开放问题（待拍板，落地页均已按保守口径标注）

1. **技能包去留**：`article-skills-plugin` / `template-skills-plugin` / `twplus-components-plugin` 现在**就在主开源仓库的 `plugins/` 目录里**——若主仓库全量公开（Gitee `xjd2020/fastcms` 现状即公开），它们事实上已是免费开源，不能既开源又上架收费。两个口径二选一：
   - **口径 A（当前落地页采用）**：随仓库免费，定位获客钩子；付费线只在业务插件；
   - **口径 B**：从开源仓库移出（私有仓库 / 仅市场分发），以技能包为低价入门商品。需要动仓库结构，且与"核心永久免费"叙事需要一次清晰切割。
2. **订阅定价**：¥199 起/月为示例；三档折扣与年付力度未定。
3. **付费插件发放方式**：授权码 + 私有下载链接（一期，推荐）vs 完整发放系统（二期再议）。
4. **官网部署方案**：静态托管（GitHub/Gitee Pages 或自建 nginx）+ 域名证书，当前 `fastcms.xiaojudeng.net.cn` 不可达待修。
5. **`fastcms-plugins` 仓库公开策略**：影响"付费插件"是否成立（全公开则付费线只剩定制）。
