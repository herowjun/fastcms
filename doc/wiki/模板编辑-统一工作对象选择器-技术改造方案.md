## 1. 背景与目标（一页）

### 1.1 现状痛点（三个割裂入口 + 双锚点）

模板编辑页当前有**三个入口**分散管理"当前在操作什么"：

| # | 入口 | 位置 | 数据源 | 问题 |
|---|---|---|---|---|
| ① | "作用模板"下拉 | edit.vue 工具栏（两个 el-select 按视图切换） | 正式模板表（templateList） | 只选到正式模板，选不到会话 |
| ② | 对话头"会话"下拉 | aiChat.vue 头部右上（sessSelect） | ai_template_session 全部会话（调整+生成） | 会话级，用户分不清"对象"和"会话" |
| ③ | "历史记录"按钮 | edit.vue 工具栏（仅 AI 视图） | ai_template_session 生成会话子集 | **点击后顶栏下拉不变 → 混淆**（用户已报障） |

同时工具栏行存在**双锚点**：左侧"作用模板"下拉 + （改造前原型中）头部模板名 chip，显示同一份"当前对象"信息，二者一旦失步即产生"信哪个"的困惑——这正是③号入口混淆问题的同根病灶。

### 1.2 根因（已核实代码）

点击"历史记录"某行后：`aiWorkbench.onOpenHistorySession`（L443-452）只改组件内部 `sessionView=true` + `applySession(row)`，**父组件 `state.loadedTemplateId` 不动**（edit.vue L243），于是顶栏下拉仍显示原正式模板，文件树/预览却已切到会话工作目录——"顶栏说的"和"三列显示的"是两回事。

### 1.3 目标

把三个入口收敛为**一个"工作对象选择器"**（工具栏单按钮 + 三页签对话框），并把"当前对象"提升为**父组件（edit.vue）持有的唯一状态**，三列（文件树/预览/对话）随其联动。同时消灭双锚点：工具栏只留选择器这一个对象指示器，头部不再放模板名 chip。

## 2. 设计决策（用户已拍板，2026-09）

| # | 决策 | 依据 |
|---|---|---|
| D1 | **单锚点**：同一份"当前对象/状态"信息在界面只出现一处（选择器按钮）；头部模板名 chip 删除。信息架构按行分工正交——头部行答"在哪个视图"（AI 工作台/手动编辑），工具栏行答"在哪个对象"+操作 | 用户两次拍板；双锚点=失步风险，失步是"点历史记录顶栏不动"那类混淆的根因 |
| D2 | **统一选择器**：对话框三页签——`正式模板` / `未应用` / `已应用`，同现有"历史生成记录"弹窗的 tab 模式（el-tabs + el-badge 计数），加一个"正式模板"页签 | 用户提出：未应用记录会越积越多，滚动长列表显示不下；与既有历史弹窗同构，心智零迁移 |
| D3 | **已应用 = 档案**：应用后模板已转为正式目录，后续调整在"正式模板"页签进入；对话框"已应用"页签**仅回看生成过程**，行操作为「回看会话」+「去正式模板」，不提供"应用"按钮 | 用户明确："已应用的模板实际上是转成正式目录了，后续可能直接在正式目录里面进行调整修改" |
| D4 | **分层锚点不变**：对话头"会话"下拉（aiChat sessSelect）保留——工具栏=对象级锚点，对话头=会话级锚点，二者正交（对象回答"在哪个模板/草稿上"，会话回答"跟 AI 聊到哪一段"） | 既有设计原则（控制件自身即指示器时不加并排文字标签），本次不动 aiChat |
| D5 | **边界**：零新依赖、零新路由、零配置开关；前端改动为主，后端仅 P2 可选项（一个字段，见 §4.9） | 用户红线：核心永免费，不加用户可见门控步骤 |

## 3. 现状盘点（坐标见 §9，均 2026-09-18 核实）

### 3.1 可复用资产（本次改造的主体是"接线"而非"重写"）

| 资产 | 坐标 | 复用方式 |
|---|---|---|
| 会话打开链路 | aiWorkbench.vue L443-452 `onOpenHistorySession(row, sessions)` → sessionView=true + applySession + loadSessionFileTree + initPreviewEntry + selectDefaultEntry | 原样保留，仅把触发入口从内部对话框上提为父组件 ref 调用（需补进 defineExpose） |
| 应用链路 | aiWorkbench.vue L540-561 `onApplyTemplate` → `aiApi.applyTemplate(sessionId)` → 后端 `AiTemplateGenServiceImpl.applyTemplate`（L3766，含同名模板互斥锁 L245/L3794）→ 返回 **`ApplyResult{message, templateId}`**（IAiTemplateGenService L183，**应用后正式模板 ID 后端已算好**）→ `emit('applied', templateId)` | 原样保留；P2 仅补"把该 templateId 持久化回会话记录" |
| 编辑此模板链路 | aiWorkbench.vue L567-575 `onEditApplied`（按 `templateName` 在 templateList 里 find）→ `emit('edit-applied', tpl.id)` → edit.vue L411 `onEditAppliedTemplate`（loadTemplateList + 切手动编辑 + dirty 确认） | 链路保留；**按名匹配是脆弱点**，P2 改为按持久化指针 |
| 历史列表数据 | CreateTemplateDialog.vue L292-302 `loadHistory`：`aiApi.listSessions()` 全量返回后前端过滤 `!s.templateId` | 过滤逻辑上提到 WorkObjectDialog；`listSessions`（api/ai/index.ts L100-102 → AiTemplateController L87-90，**无分页，返回 List**）不动 |
| 未应用/已应用表格 UI | CreateTemplateDialog.vue L60-112（el-tabs 双页签 + el-badge 计数 + el-table + el-empty + history-tip） | 整段迁入 WorkObjectDialog 的"未应用/已应用"页签，样式类名随迁 |
| 模板列表数据 | edit.vue `state.templateList`（templateApi.getTemplateList），`onTemplateChange`（L636）/`onScopeChange`（L309）切换逻辑 | 原样保留，作为选择器选"正式模板"行的落地动作 |
| dirty 保护 | edit.vue L417-427 `checkDirty`/`confirmDiscard` | 切换工作对象时复用（与现有"编辑此模板"同款） |

### 3.2 数据模型（核实）

`ai_template_session`（service/src/main/java/com/fastcms/entity/AiTemplateSession.java）一表两型：

- `templateId` 非空 → **调整会话**（作用对象=正式模板）
- `templateId` 为空 → **生成会话**（`templateName` 为拟名；`workDir` 指向预览工作目录，L78-80 注释明确）
- `status` ∈ {`active`, `applied`, `closed`}（AiTemplateConstants.java L81-83）；"生成中/失败"为前端内存态（SSE 期间），不落库
- **没有"应用后指向哪个正式模板"的字段**——P2 补 `applied_template_id`

## 4. 详细设计

### 4.1 总体状态机（核心：对象状态上提到 edit.vue）

新增**父组件级"工作对象"状态**，三列联动从"组件内部各自切"变为"父组件单点驱动"：

```
WorkObject =
  | { kind: 'template', templateId: string }              // 正式模板
  | { kind: 'session',  session: AiTemplateSession }      // 生成会话（草稿/生成中/已应用）
```

**唯一写入口** = WorkObjectDialog 行点击 → `edit.vue: selectWorkObject(obj)`。
所有"三列该显示什么"由 `currentWorkObject` 这一个 ref 推导（computed），禁止任何组件私改对象归属。

```
selectWorkObject(obj)
  ├─ dirty 检查（checkDirty → confirmDiscard，沿用 L417-427）
  ├─ obj.kind === 'template'
  │    state.loadedTemplateId = obj.templateId            // 现有 onTemplateChange 链路
  │    aiWorkbenchRef.exitSessionView()                   // 新增 expose：sessionView=false，回正式模板树
  └─ obj.kind === 'session'
       aiWorkbenchRef.openSessionByRow(obj.session)       // 现有 onOpenHistorySession，补 expose
       （loadedTemplateId 不动 —— 会话视图下树/预览走会话工作目录，与现状一致）
       currentView.value = 'ai'                            // 会话只能在 AI 工作台打开（草稿态无代码编辑器可编辑）
```

**选择器按钮显示**（computed，与原型一一对应）：

| 当前对象 | 图标 | 名称 | 状态标签 | 按钮样式 |
|---|---|---|---|---|
| 正式模板·使用中 | ▦ | templateName | 使用中 | 默认 |
| 正式模板·未激活 | ▦ | templateName | 正式模板 | 默认 |
| 生成会话·active | ✦ | session.templateName | 生成中·会话工作目录 / 草稿·会话工作目录（按 isChatting/isFailed 内存态） | `.selbtn.draft`（紫） |
| 生成会话·applied | ✓ | session.templateName | 已应用·只读回看 | `.selbtn.applied`（绿） |

> 原型里 `selName/selTag` 即此映射的演示实现（原型 applyAll 第 1 步）。

### 4.3 WorkObjectDialog 详细设计

**Props / Emits**：

```ts
props: {
    visible: boolean;                  // v-model:visible
    templateList: any[];               // 正式模板（父组件 state.templateList）
    sessions: any[];                   // 全部会话（父组件统一 listSessions 拉取，见 §4.5）
    badgeCtx?: { runningId?: string; failedId?: string };  // 内存态徽章（沿用 openHistoryDialog L585-589 的取法）
}
emits: {
    (e: 'update:visible', v: boolean): void;
    (e: 'select', obj: { kind:'template'; templateId:string } | { kind:'session'; session:any }): void;
    (e: 'create'): void;               // 对话框内"新建模板" → 父组件切 create 表单模式（同一对话框内）
    (e: 'goto-template', templateId: string): void;  // 已应用行"去正式模板"（= select template，语义独立便于埋点/提示）
}
```

**三页签**（el-tabs，命名对齐现有：`tpl` / `pending` / `applied`）：

| 页签 | 数据 | 行内容 | 行操作 |
|---|---|---|---|
| 正式模板 `<el-badge :value="templateList.length">` | `templateList` | 名称 + （使用中?）、N 个页面 · 最近修改 | 行点击=`select {kind:'template'}`；按钮「手动编辑」「AI 调整」（= 同一 select + currentView 切换） |
| 未应用 | `sessions.filter(s=>!s.templateId && s.status!=='applied')` | templateName + 状态徽章（生成中/进行中/失败，badgeCtx 内存态覆盖）+ 需求摘要 + 时间 | 行点击=`select {kind:'session'}`（打开续聊）；按钮「应用」 |
| 已应用 | `sessions.filter(s=>!s.templateId && s.status==='applied')` | templateName + 已应用徽章 + 需求摘要 + 时间 + "已转为正式模板" | 行点击=`select {kind:'session'}`（只读回看）；按钮「去正式模板」= `goto-template`（按 applied_template_id 或 templateName 解析，§4.7） |

- **默认页签跟随当前对象**（`defaultTab()`）：当前=会话且 applied→`applied`；当前=会话→`pending`；否则→`tpl`。打开即见"我在哪"。
- **搜索框**：模板页签搜名称，会话页签搜 templateName+requirement（对齐原型 `match()`）。
- **每页签一句 hint**（对齐原型 TAB_META）：明确"已应用仅回看，后续调整去正式模板页签"（D3 的 UI 落地）。
- 表格样式、空态（el-empty）、badge 计数全部沿用 CreateTemplateDialog 现有类名（`.history-session-table` 等），视觉零漂移。

**4.3.4 "新建模板"入口归位**：原型里对话框右下角有"✦ 新建模板"。实现上两种落法：
- **推荐**：WorkObjectDialog 复用 CreateTemplateDialog 的**新建表单**作为第四态（`view:'create'`），对话框内 tab 不变、内容区切表单——与现状"新建模板/历史生成记录"双视图同一容器，改动最小（CreateTemplateDialog 本就有双视图机制，只是把 history 换成 WorkObjectDialog 的三页签后，create 视图原样保留）。即：工具栏"新建模板"按钮 → 打开对话框并 `focusView='create'`。
- 备选：工具栏保留独立"新建模板"按钮打开纯表单。——不推荐，又造一个入口。

### 4.6 事件流对照（改造前 → 改造后）

| 场景 | 改造前 | 改造后 |
|---|---|---|
| 切换正式模板 | 工具栏下拉 → onTemplateChange | 对话框正式模板页签行点击 → selectWorkObject(template) → onTemplateChange |
| AI 调整某模板 | 同上（v-else 下拉） | 同上（对话框"AI 调整"按钮 = select + currentView='ai'） |
| 打开草稿续聊 | 历史记录按钮 → 历史弹窗行点击 → onOpenHistorySession | 对话框未应用页签行点击 → selectWorkObject(session) → aiWorkbenchRef.openSessionByRow |
| 应用草稿 | AI 视图工具栏"应用模板"（showApply 时显示） | **不变**（按钮留在工具栏，属"会话级操作"；对话框行内「应用」= 同一 onApplyTemplate） |
| 回看已应用 | 历史记录弹窗→已应用 tab 行点击 | 对话框已应用页签行点击 → openSessionByRow（sessionView=true，只读回看，isApplied 逻辑不动） |
| 编辑应用后的模板 | 工具栏"编辑此模板"（showEditApplied）→ onEditApplied（按名匹配） | 对话框已应用行「去正式模板」→ goto-template → onEditAppliedTemplate；工具栏"编辑此模板"保留（回看态下就地入口） |
| 新建模板 | 工具栏"新建模板" → createDialog open() | 工具栏"新建模板" → 对话框 create 态（§4.3.4） |



### 4.7 P2：`applied_template_id` 指针（消除按名匹配的脆弱点）

**问题**（现状核实）：`onEditApplied`（aiWorkbench L567-575）用 `currentSession.templateName` 在 `templateList` 里 `.find(i => i.name === name)` 反查正式模板 ID。重名模板 / 模板被改名 / 目录名与注册表不一致时失配，只剩"未找到对应的正式模板"兜底提示。而**后端 apply 时其实已经算出了正确的 templateId**（`ApplyResult.templateId`，IAiTemplateGenService L181-183），只是没回写持久化。

**改法**（极小，P2 独立排期）：
1. **实体 + DDL**：`AiTemplateSession` 加字段 `appliedTemplateId`（String，`@TableField("applied_template_id")`）；4 份全量 DDL 同步加列（见 §9 附录 A 清单）。列放 `template_id` 之后，AFTER 锚点用 `template_id`（该列 4 份 DDL 均存在，已核实实体有此字段即表有此列）。
2. **后端赋值**：`AiTemplateGenServiceImpl.applyTemplate`（L3766）在 apply 成功、算出 templateId 后，`updateById` 把 `appliedTemplateId` 写回该会话行（与 status→applied 同事务）。`listSessions` 无需改动（整实体返回，新字段自动带出）。
3. **前端**：`onEditApplied` 改读 `currentSession.appliedTemplateId`，存在则直接用（emit edit-applied 该 id），缺失（存量数据）才回退按名匹配 + 现有兜底提示。
4. **存量数据**：历史已应用会话 `applied_template_id` 为 NULL → 回退按名匹配（不劣化现状）。可选补一条 UPDATE 按 templateName 回填，但重名风险仍在，建议**不回填、靠回退**，新数据起自然全走指针。

> 此步 P0/P1 完全不依赖，可独立于选择器改造排期；但 P1 的"去正式模板"在 P2 落地前走的是按名匹配（与现状 onEditApplied 同一逻辑），不劣化。

## 5. 复用清单 vs 新建清单（标量级）

## 7. 验收清单（对照原型逐条）

1. 顶栏只有一个对象控件；点任意对话框行后 **选择器按钮 / 文件树 / 预览 / 对话 pill 四处一致**（不变式，原型 demo-bar 所述）。
2. 对话框三页签 + 计数；计数随应用动作实时流转（原型：3/2/1 → 4/1/2）。
3. 默认页签跟随当前对象（tpl→正式模板页签；草稿→未应用；回看→已应用）。
4. 草稿行「应用」→ 状态流转 applied、会话进只读、正式模板列表新增同名项。
5. 已应用行「去正式模板」→ 加载正式模板到手动编辑（dirty 保护生效）。
6. 草稿态下选"手动编辑"被阻止并提示（强制切 AI 工作台）。
7. 对话头会话下拉（aiChat）行为不变（调整/未应用/已应用三组）。
8. 未保存修改保护：切对象前弹确认（checkDirty 链路）。
9. 手动编辑视图下选择器不可落到未应用草稿。

## 8. 风险与开放问题

| # | 风险/开放项 | 处理 |
|---|---|---|
| R1 | 未应用记录量大时（几十条）单页签仍长 | 现有 el-table max-height 滚动已够用；若再增长，列表接口加分页属后续独立需求，本次不动（listSessions 现状无分页，已核实） |
| R2 | 对话头下拉与对话框未应用页签**数据重叠**（同一批生成会话出现在两处） | 有意为之（D4）：对话头=当前模板作用域内的会话快捷切换（含调整会话），对话框=全量对象管理。二者回答不同问题，不算双锚点（不同维度：会话 vs 对象）。需在 UI copy 上措辞区分（"会话" vs "工作对象"），避免用户误认重复 |
| R3 | CreateTemplateDialog 双视图机制删减后，create 表单嵌进 WorkObjectDialog 的 create 态，嵌套 dialog 层级 | 推荐落法（§4.3.4）是**同一对话框内切内容区**而非 dialog 套 dialog，无层级问题；备选方案（独立按钮开表单）则完全无嵌套，代价是多一个入口——若实现中发现 create 态内切换体验别扭，回退备选 |
| R4 | `onScopeChange`（L309）删除前需确认无其他调用点 | 已 grep：仅工具栏 v-else 下拉一处调用（L24）；P1 落地时再全仓 grep 一次 |
| R5 | 已应用"去正式模板"在 P2 前仍按 templateName 匹配 | 现状即是如此（onEditApplied L567-575），P2 前不劣化；重名模板场景的兜底提示已存在（"未找到对应的正式模板"） |
| R6 | open 对话框的会话列表刷新时机 | 打开时刷新一次 + 应用/创建/状态变化后刷新（§4.5）；不做轮询（用户既定偏好：布局/状态同步不用轮询） |
